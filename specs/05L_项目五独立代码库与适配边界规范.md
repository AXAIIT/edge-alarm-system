# 05L_项目五独立代码库与适配边界规范

## 目的

本规范用于明确项目五与项目一、项目三、项目四之间的边界。项目五可以继承前序项目的模型产物、环境基线、benchmark 证据和失败结论，但最终运行代码必须在项目五目录内形成独立代码库，不能把项目三或项目四的脚本直接当成项目五最终系统入口。

项目五最终要交付的是“边缘告警解释系统”，而不是“调用项目三 detector 脚本后再调用项目四模型脚本的命令集合”。因此必须区分：

| 类型 | 是否允许 | 用途 |
|---|---|---|
| 前序项目报告和 benchmark 证据 | 允许 | 作为环境基线、模型准入、检测基线和失败结论 |
| 共享模型文件 `models/` | 允许 | 作为项目五 detector/LLM/VLM runtime 的模型输入 |
| 前序项目 raw result | 允许 | 作为 replay、接口 smoke、后处理链路验证 |
| 直接执行项目三/项目四脚本 | 仅临时允许 | 只能作为 legacy smoke 或证据复现，不能作为最终 resident service |
| 项目五服务入口和 worker | 必须项目五本地实现 | 最终系统验收、常驻服务、并发稳定性 |

## 独立代码库原则

项目五运行时代码必须集中在：

```text
projects/05_alarm_system/
  scripts/
    run_demo/
    benchmark/
    monitor/
    report/
    service/
  src/
    detector/
    event_trigger/
    frame_sampler/
    llm_client/
    vlm_client/
    alarm_output/
    service/
  configs/
```

最终系统入口必须来自 `projects/05_alarm_system/scripts/service/` 或 `projects/05_alarm_system/src/service/`。如果需要调用 TensorRT、RKNN、llama.cpp、RKLLM 或 Qwen3-VL runner，项目五应提供本地 adapter/wrapper，并把外部二进制作为可配置 artifact，而不是硬编码调用项目三/项目四脚本。

## 允许继承的边界

| 继承项 | 合法使用方式 | 不合法使用方式 |
|---|---|---|
| 项目三 detector raw | 读取 JSONL，生成 event package，验证事件规则和 JSON 闭环 | 声称项目五已实现常驻 DetectorService |
| 项目三 pipeline 报告 | 作为 detector FPS/p95/drop 基线 | 替代项目五并发服务验收 |
| 项目四模型准入报告 | 决定 LLM/VLM 是否进入项目五路线 | 替代项目五真实 event_id 对齐运行 |
| 项目四 runner 经验 | 迁移实现项目五本地 adapter | 直接把项目四脚本作为项目五最终 worker |
| 共享模型文件 | 通过项目五配置传入路径和 hash | 在项目五报告里缺失模型 hash 或路径证据 |

## 跨项目引用分级

项目五中出现 `projects/03_video_pipeline` 或 `projects/04_llm_vlm_independent` 时，必须按下面类别说明：

| 分类 | 示例 | 可进入最终验收 |
|---|---|---|
| `allowed_reference` | 报告、规范、benchmark 结论路径 | 可以，作为证据引用 |
| `allowed_artifact` | `benchmark/raw/03_video_pipeline/...`、`models/llm_vlm/...` | 可以，作为输入 artifact |
| `legacy_adapter_smoke` | `run_detector_adapter.py` 读取项目三 raw；或手工指定项目四 wrapper 路径 | 不能，只能作为 smoke 或后处理链路 |
| `forbidden_final_runtime` | resident service 中直接执行项目三/项目四脚本作为主 worker | 不能 |

报告中必须显式写出 `code_boundary_status`：

| status | 含义 |
|---|---|
| `independent_runtime_pass` | 项目五服务入口、队列、worker、adapter 均在项目五目录内 |
| `artifact_replay_pass` | 读取前序 raw/artifact 完成项目五后处理链路 |
| `legacy_adapter_smoke` | 仍直接执行前序项目脚本或 wrapper，仅作单次 smoke |
| `coupled_runtime_not_accepted` | 最终服务仍依赖前序项目脚本，不能验收 |

## 最终服务代码要求

项目五后续必须补齐下面本地入口，名称可调整，但职责不可缺失：

| 入口 | 职责 |
|---|---|
| `scripts/service/run_alarm_service.py` | 启动常驻 detector/event/model/alarm 服务，管理生命周期 |
| `scripts/service/detector_service.py` | 持续接入视频/摄像头 detector 输出，不能被 LLM/VLM 阻塞 |
| `scripts/service/event_queue.py` | 有界队列、冷却、去重、drop policy、queue metrics |
| `scripts/service/text_worker.py` | 项目五本地文本 LLM adapter，支持 timeout、rate limit、fallback |
| `scripts/service/vlm_worker.py` | 项目五本地 ROI/关键帧 VLM adapter，支持 timeout、rate limit、fallback |
| `scripts/service/alarm_sink.py` | 持续写入 schema-safe Alarm JSON、per-event raw 和 service log |

如果短期内无法实现常驻 VLM，可以先实现 `resident_detector_with_single_shot_workers`，但报告必须写：

```text
resident_detector=true
resident_llm=false 或 warm_pool=false
resident_vlm=true 仅当引用 `20260711_rk3588_8gb_alarm_service_resident_vlm_smoke_v1` 或后续同等级证据时成立
code_boundary_status=independent_runtime_pass
service_claim=not_verified
```

## 代码检查命令

每次最终验收前必须执行：

```bash
python3 projects/05_alarm_system/scripts/benchmark/check_code_boundary.py \
  --root projects/05_alarm_system \
  --output benchmark/processed/05_alarm_system/<run_id>_code_boundary_check.md
```

判定规则：

- `scripts/run_demo/` 中读取前序 raw 或临时调用 wrapper：允许，但必须标为 `legacy_adapter_smoke`。
- `scripts/service/` 或 `src/service/` 中直接调用前序项目脚本：不允许进入最终验收。
- `reports/specs/configs` 中引用前序项目证据：允许。

## 与 05K 的关系

05K 定义常驻服务与并发验收；05L 定义代码边界。最终 Project5 完成必须同时满足：

```text
05K resident_service_required
+ 05L independent_runtime_pass
```

只满足其中一个都不能写成完整在线告警解释系统完成。
