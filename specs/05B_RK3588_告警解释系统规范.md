# 05B_RK3588_告警解释系统规范

## 适用范围

本规范用于在 RK3588 8GB 上运行项目五主线：

```text
YOLO11n RKNN 高频检测
-> 事件触发 / ROI / 短视频片段
-> Qwen3-1.7B RKLLM 文本告警解释路线；必须有项目五真实 RKLLM raw/log 才算已执行
-> Qwen3-VL 低频 ROI/关键帧复核路线；必须有真实 ROI 图片和模型调用证据才算已执行
-> 结构化告警 JSON
```

RK3588 的项目五主线是“实时检测 + 文本解释 + 低频 ROI/关键帧复核”。项目四已经完成 RK3588 Qwen3-1.7B RKLLM 文本和 Qwen3-VL RKNN/RKLLM 图文准入，二者均只能按 `B_low_frequency` 低频/异步接入；SmolVLM2 视频路线不能进入项目五视频主线，按 `D_not_used` 和检测/抽帧摘要降级。

项目四准入结果不能替代项目五真实系统执行。当前项目五 `run_llm_explain.py` 已支持 `template`、Jetson/llama.cpp 和 RK3588 `rkllm` 路线；RK3588 文本解释只有通过项目五本地 RKLLM adapter 调用 runner，并输出项目五 event_id 对齐的 raw/log/metrics 后，才能写 `llm_execution=rkllm_qwen3`。否则只能写 `llm_execution=template` 或 `not_executed`。已验证的 Project5 RKLLM text smoke 为 `20260708_rk3588_8gb_alarm_system_rkllm_text_smoke_v1`，LLM rows=3、bad=0、runtime-log contaminated rows=0。

当前项目五 `run_vlm_roi_qa.py` 已支持 `stub` 和 `rkllm_multimodal` 两种路线。真实 RK3588 Qwen3-VL 复核必须以项目五 event package 的 `keyframe_path` 或 `roi_paths` 作为输入；如果事件包只有 `roi_boxes`，必须先通过 `extract_event_assets_from_video.py` 从 Project3 保存的视频中抽帧和裁 ROI。没有真实图片资产时，即使项目四 Qwen3-VL 已准入，也只能写 `vlm_execution=route_stub_only`、`not_executed` 或 `blocked_no_image_asset`，不能写成项目五真实 VLM。

RK3588 最终系统目标按 `projects/05_alarm_system/specs/05K_常驻服务与并发验收规范.md` 执行：RKNN detector 必须常驻，事件队列必须异步有界，RKLLM 文本和 Qwen3-VL 只能低频消费事件，不能同步阻塞 detector。当前 `rkllm_single_turn` 和 `rkllm_multimodal_once` 结果只能证明 single-shot model smoke；若仍然每次事件都重新加载模型，不能写成 resident LLM/VLM。

代码边界按 `projects/05_alarm_system/specs/05L_项目五独立代码库与适配边界规范.md` 执行。当前 RK3588 文本和 VLM 默认 wrapper 已迁到项目五本地 runtime adapter，但仍是 single-shot 调用；最终验收需要把 RKLLM text adapter、Qwen3-VL adapter、队列和 AlarmSink 收敛到项目五本地常驻 service 入口。

RK3588 从当前分步证据到最终系统必须按 `projects/05_alarm_system/specs/05M_常驻告警系统实施路线图.md` 的 P3、P5、P6、P7、P8 顺序执行：先用已编译的 Project5 本地 RKNN runner 完成真实 10 分钟 template/stub detector smoke，再补服务内 ROI 资产，再实现本地常驻/warm RKLLM 文本和 Qwen3-VL worker，最后进行 10 分钟和 30 分钟全链路验收。P3 detector 必须固定使用项目三已验证并由 Project5 本地 pipeline 继承的 `models/yolo11n/rknn/yolo11n_640_rk3588_rknnopt_int8_ptq_calib500.rknn`，SHA256 为 `40bce507d584498825267287cbb44c8dd860c8ddc3413677767891aeb225b69c`。P3 之前的 RKLLM/VLM raw 仅是 P1 single-shot 证据，不能跳阶段写成 resident service。

告警业务语义以 `projects/05_alarm_system/specs/05H_告警业务语义与事件规则规范.md` 为准。RK3588 第一阶段直接由 YOLO 检测触发的 `visual_detection` 候选告警只包含 `person_presence`、`vehicle_presence`、`multi_object_scene` 三类；同时必须结构化记录 `text_explanation`、`visual_evidence`、`system_runtime`、`model_runtime`、`json_quality` 和 `video_fallback` 等解释/降级任务。

## 执行原则

可以替换 RKNN pipeline 调用方式、LLM runtime、服务框架和监控工具，但不能降低证据要求：必须证明 RKNN 检测和文本 LLM 解耦，必须记录 LLM 是否挤占检测链路资源，必须显式说明 VLM/视频理解的准入等级和禁用原因。最终服务化验收以 05K 为准；本文件中的分步命令默认只构成模块证据或后处理链路证据。

## 前置条件

- 项目三 RK3588 pipeline 可运行，并有检测 FPS、p95、队列和稳定性记录。
- 项目四 RK3588 上 Qwen3-1.7B RKLLM 准入完成：`B_low_frequency`，selected evidence `20260701_rk3588_8gb_qwen3_1_7b_rkllm_text_ctx2048_formal_v2 + quality_v1 + quality_v2`，p50 约 `15168.15 ms`，p95 `26628.865 ms`，decode `12.712 tok/s`。
- 项目四 RK3588 上 Qwen3-VL RKNN vision + RKLLM decoder 准入完成：`B_low_frequency`，selected evidence `20260703_rk3588_8gb_qwen3_vl_2b_rknn_rkllm_image_cn_formal_v2_max512`，p50 `21391.0 ms`，p95 `57199.9 ms`，质量 `pass_with_caveat`。
- 项目四 RK3588 SmolVLM2 视频路线不进入项目五主线；视频摘要必须来自检测、抽帧、ROI/VLM 复核和文本 LLM。
- 已准备 RK3588 事件规则、prompt 模板和告警 schema。
- 已确认事件规则使用 `projects/05_alarm_system/configs/event_rules/rk3588_rules.yaml` v2，且 `class_filter` 非空。
- 已建立 RK3588 环境基线，记录 RKNN/RKNPU、LLM runtime、电源模式、散热、swap。
- 环境基线必须对齐 `projects/05_alarm_system/specs/00_environment_baseline_template.md`。
- run 记录必须对齐 `projects/05_alarm_system/specs/00_run_record_template.md`。
- per-event raw 必须符合 `benchmark/schemas/alarm_system_raw_schema.json`。
- event package 必须符合 `benchmark/schemas/alarm_event_package_schema.json`。
- 告警 JSON 必须符合 `projects/05_alarm_system/configs/alarm_schema/alarm_event_schema.json`。

如果后续执行环境与上述项目四准入证据不一致，RK3588 项目五主线必须标记为 `blocked` 或 `not_verified`，只能用规则模板或 mock 输出联调 JSON，直到重新完成模型准入或系统复测。

## 执行步骤

### 1. 冻结模型组合

新建 `projects/05_alarm_system/runs/<date>_rk3588_8gb_alarm_combo_freeze/run.md`，记录：

- YOLO11n RKNN artifact。
- Qwen3-1.7B 模型路径、hash、runtime、量化格式。
- 上下文长度、max output token、超时阈值。
- VLM 状态：Qwen3-VL `B_low_frequency`，低频 ROI/关键帧复核；视频状态：SmolVLM2 `D_not_used`，默认禁用。
- 项目四证据路径。

### 2. 启动 RKNN 检测链路

推荐命令：

```bash
python3 projects/05_alarm_system/scripts/run_demo/run_detector_adapter.py \
  --board-config projects/05_alarm_system/configs/boards/rk3588_8gb.yaml \
  --source <camera_or_video> \
  --project3-raw <project3_frame_level_jsonl> \
  --output benchmark/raw/05_alarm_system/rk3588_8gb/<date>_rk3588_detector_events.jsonl \
  > logs/runtime/05_alarm_system/rk3588_8gb/<date>_rk3588_detector_adapter.log 2>&1
```

必须保留 RKNPU 调用证据或项目三相应证据引用。

### 3. 生成事件包

```bash
python3 projects/05_alarm_system/scripts/run_demo/run_event_trigger.py \
  --detections benchmark/raw/05_alarm_system/rk3588_8gb/<date>_rk3588_detector_events.jsonl \
  --rules projects/05_alarm_system/configs/event_rules/rk3588_rules.yaml \
  --output benchmark/raw/05_alarm_system/rk3588_8gb/events/<date>_rk3588_event_packages.jsonl \
  > logs/runtime/05_alarm_system/rk3588_8gb/<date>_rk3588_event_trigger.log 2>&1
```

事件包必须包含 event_id、alarm_domain、alarm_type、event_stage、frame_id、timestamp、detections、keyframe_path、roi_paths、video_clip_path。当前第一阶段 `event_stage` 应为 `candidate`，不得写成完整业务告警验收通过。

### 4. 文本解释接口联调或真实 RKLLM 适配

下面命令只能作为项目五 JSON 闭环的 template 接口联调，不能写成 RKLLM 真实执行：

```bash
python3 projects/05_alarm_system/scripts/run_demo/run_llm_explain.py \
  --events benchmark/raw/05_alarm_system/rk3588_8gb/events/<date>_rk3588_event_packages.jsonl \
  --model-config projects/05_alarm_system/configs/models/rk3588_model_combo.yaml \
  --prompt-template data/prompts/alarm_text_explain.md \
  --mode template \
  --output benchmark/raw/05_alarm_system/rk3588_8gb/<date>_rk3588_qwen3_text_outputs.jsonl \
  > logs/runtime/05_alarm_system/rk3588_8gb/<date>_rk3588_qwen3_text.log 2>&1
```

真实 RK3588 文本解释必须满足下面条件后才允许写入正式能力结论：

- 使用项目四已验证的 RKLLM runner，或新增项目五 RKLLM adapter。
- 输入来自项目五 event package，并按 `event_id` 输出文本解释 raw。
- 记录 first token、tokens/s、total time、memory、swap、temperature、RKLLM runtime 日志和是否影响检测 FPS。
- `model_execution.llm_execution` 写 `rkllm_qwen3`；若只是上面的 template 命令，必须写 `template`。

### 5. VLM/视频理解降级处理

Qwen3-VL 只能低频异步执行，不能进入实时逐帧链路。只有同时满足下面条件才允许执行 ROI/关键帧复核：

- 项目四给出 RK3588 对应模型 `B_low_frequency` 或更高等级。
- 项目五 event package 中存在真实 `keyframe_path` 或 `roi_paths`，路径可读取。
- 已有 RKNN vision + RKLLM decoder 的项目五 runner 或 adapter，且输出按 `event_id` 对齐。当前推荐入口是 `run_vlm_roi_qa.py --mode rkllm_multimodal`，默认使用项目五本地 `scripts/service/runtime_adapters/run_rkllm_multimodal_once.sh` wrapper。
- 项目五配置中设置明确调用频率和超时。
- 检测链路仍满足 FPS 和队列门槛。

当前如果只有 `run_vlm_roi_qa.py --mode stub` 的 route 输出，必须写 `vlm_execution=route_stub_only`，不能把项目四 Qwen3-VL p50/p95 当成项目五系统并发 VLM 性能。如果真实模式输出 `blocked_no_image_asset`，必须回到 05D 先生成 ROI/关键帧资产，不能继续生成“真实 VLM pass”结论。

如果手工改回项目四 `run_rkllm_multimodal_once.sh`，即使真实 VLM 输出通过，也只能写 `vlm_execution=single_shot`、`code_boundary_status=legacy_adapter_smoke`、`resident_vlm=false`。使用项目五本地 adapter 时仍只能写 `vlm_execution=single_shot`；只有项目五本地常驻 worker 或 warm pool 通过 05K/05L，才能写 resident VLM。

SmolVLM2 视频理解默认禁用，必须在 `fallback_status.video` 写 `disabled_by_project4_decision`，并用文本 LLM 基于检测 JSON、关键帧/ROI 摘要和日志生成告警解释。

### 6. 生成并校验告警 JSON

```bash
python3 projects/05_alarm_system/scripts/run_demo/build_alarm_json.py \
  --events benchmark/raw/05_alarm_system/rk3588_8gb/events/<date>_rk3588_event_packages.jsonl \
  --llm benchmark/raw/05_alarm_system/rk3588_8gb/<date>_rk3588_qwen3_text_outputs.jsonl \
  --vlm none \
  --video none \
  --schema projects/05_alarm_system/configs/alarm_schema/alarm_event_schema.json \
  --model-config projects/05_alarm_system/configs/models/rk3588_model_combo.yaml \
  --output benchmark/raw/05_alarm_system/rk3588_8gb/alarms/<date>_rk3588_alarm_json.jsonl \
  > logs/runtime/05_alarm_system/rk3588_8gb/<date>_rk3588_alarm_json.log 2>&1
```

### 7. 端到端 benchmark

```bash
python3 projects/05_alarm_system/scripts/benchmark/run_alarm_system_benchmark.py \
  --board rk3588_8gb \
  --events benchmark/raw/05_alarm_system/rk3588_8gb/events/<date>_rk3588_event_packages.jsonl \
  --alarms benchmark/raw/05_alarm_system/rk3588_8gb/alarms/<date>_rk3588_alarm_json.jsonl \
  --model-config projects/05_alarm_system/configs/models/rk3588_model_combo.yaml \
  --output benchmark/raw/05_alarm_system/rk3588_8gb/<date>_rk3588_alarm_system_benchmark.jsonl \
  > logs/benchmark/05_alarm_system/rk3588_8gb/<date>_rk3588_alarm_system_benchmark.log 2>&1
```

| 类别 | 必填指标 | 当前继承基线 | 项目五要求 |
|---|---|---|---|
| 检测吞吐 | FPS avg/min/max | 项目三 RK3588 selected run 为准 | 系统整合后记录 FPS delta |

| 图文 VLM | image preprocess、VLM total、timeout rate、quality | Qwen3-VL p50 `21391.0 ms`、p95 `57199.9 ms`、quality `pass_with_caveat` | 只低频 ROI/关键帧调用 |
| 视频理解 | clip duration、sampled frames、decode/preprocess/generate | SmolVLM2 `D_not_used` | 默认禁用；写明 fallback |
| 告警 JSON | schema pass、fact conflict、repair count、event trace pass | 无继承基线 | alarm JSON 必须校验 |
| 资源 | memory、swap、temperature、power、CPU/NPU util | 项目三/四有单链路基线 | 系统并发必须重新采样 |
| 稳定性 | 10 min smoke、30 min required、120 min target | 项目三检测稳定性可继承 | 项目五系统至少 30 min |

## 验收标准

- YOLO11n RKNN 检测、事件包、文本解释输出和告警 JSON 链路可运行；Qwen3-1.7B RKLLM 与 Qwen3-VL 只有在项目五真实模型 raw/log/monitor 齐全时才允许写成已运行。
- 事件规则按 05H 生成候选告警，且不使用 `generic_object_event`。
- 文本 LLM 调用不导致检测队列不可控堆积。
- 告警 JSON schema 合格。
- VLM/视频理解状态清晰：Qwen3-VL 为低频异步路线或 `route_stub_only/not_executed`，SmolVLM2 视频禁用。
- 内存、swap、温度、功耗或电源模式完整。

## 降级和问题库

下面问题必须进入 `projects/05_alarm_system/reports/troubleshooting.md`：

- Qwen3-1.7B 项目四准入缺失。
- LLM 过慢导致告警延迟不可控。
- LLM 运行导致检测 FPS 明显下降或队列堆积。
- VLM/视频被误写成实时链路。
- RKNPU fallback 异常、内存不足、swap 过高、温控降频。
